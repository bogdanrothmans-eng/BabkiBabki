# Бабки — общий бюджет на двоих

Веб-сервис для пары, которая ведёт траты в Google Таблице «категории × месяцы».
Работает и на телефоне, и на десктопе. Второго человека можно пригласить по ссылке:
вы вместе вносите траты, комментируете их и прикладываете чеки.

## Что умеет MVP

- **Главная сумма в центре.** «Потрачено в июле — 52 288 ₽» крупно, под ней спокойное
  сравнение с прошлым периодом без красных «провалов», доход, остаток и кто сколько платил.
- **Любой период**: месяц, год или произвольный диапазон, стрелки ← → для соседнего периода.
- **Быстрый ввод**: сумма, 8 самых частых категорий, «сегодня / вчера», кто платил,
  комментарий и фото чека. На телефоне форма открывается снизу, на десктопе диалогом.
- **Совместный доступ**: одноразовая ссылка-приглашение на 7 дней. Все участники
  видят и правят общие записи.
- **Комментарии** к каждой записи (переписка двух людей) и **чеки/фото**: фото сжимаются
  в браузере до ~300 КБ и отдаются только участникам бюджета.
- **Редактирование** суммы, категории, даты, плательщика и удаление записи.
- **Свои категории**: можно добавлять, переименовывать, менять иконку и архивировать
  (архив не ломает прошлые месяцы).
- **«Таблица»**: тот же вид «категории × месяцы», что у знакомых в Google Sheets,
  с итогами и переходом из ячейки к записям.
- **Импорт из Google Таблицы** (CSV): строки сопоставляются с категориями
  («Чипсы Пиво» → «Чипсы и пиво», «Садоводчество» → «Садоводство», «Работа Миша» →
  «Работа» с пометкой «Миша»). Повторный импорт года заменяет данные, а не дублирует их.

Компоненты взяты из [shadcn/ui](https://github.com/shadcn-ui/ui) (new-york-v4) и лежат
в `src/components/ui`.

## Разбор исходной таблицы

Лист «Статистика трат по категориям за каждый месяц»: 38 категорий расходов в строках,
12 месяцев в столбцах, внизу «ИТОГ МЕСЯЦА». Заполнены январь, июнь и июль.

**Что хорошо**
- Подробные, жизненные категории («Чипсы Пиво», «Расходы на окружающих»,
  «Нежелательные траты + кредиты»), их не нужно придумывать заново.
- Видно весь год одним экраном, легко сравнивать месяцы.
- Таблица общая: её ведут вдвоём.

**Что мешает**
- **Итог врёт.** В январе «Активности» записаны как `4 153` с пробелом. Google Sheets
  считает это текстом, и `SUM()` его пропускает: в таблице январь = 59 669 ₽, на самом
  деле 63 822 ₽ (−6,5%). Сервис принимает любые форматы чисел и предупреждает о таком при импорте.
- **Только суммы за месяц.** Не видно, из чего сложилось «Продукты: 12 429», когда и кто
  платил. Сервис хранит каждую трату отдельно, а месяц считает сам.
- **Люди зашиты в категории**: «Работа <имя>» отдельно для каждого. В сервисе одна категория
  «Работа», а плательщик указывается у каждой записи.
- **Нет доходов, остатка и сравнения с прошлым месяцем.** В сервисе всё это есть
  на главном экране.
- **Треть категорий пустая** (13 из 38 ни разу не заполнены), а форма с 38 вариантами
  на телефоне неудобна. В сервисе сверху 8 самых частых категорий, остальные под кнопкой.
- **С телефона вносить неудобно**: мелкие ячейки, нет «сегодня», нельзя приложить чек или
  оставить комментарий. Именно поэтому февраль–май, судя по всему, пустые.
- Опечатки в заголовках («декаюрь», «Садоводчество»), «Февраль» с итогом 0.

## Запуск

Нужен Node.js ≥ 22.13: база — встроенный `node:sqlite`, нативные модули не нужны.

```bash
npm install
npm run seed            # демо: Аня и Миша, пароль babki123, история из seed/sheet-sample.csv
npm run dev             # http://localhost:3000
```

`npm run seed -- путь/к/вашей.csv 2026` импортирует вашу выгрузку. База и загруженные
фото лежат в `data/` (папка в `.gitignore`), путь меняется переменной `DATA_DIR`.

`seed/sheet-sample.csv` — обезличенная копия таблицы знакомых: та же структура и
категории, суммы изменены, имена заменены. Сохранена ловушка с `4 603` через пробел.

## Проверки

```bash
npm run typecheck
npm run lint
npm test                                             # unit: парсер таблицы, деньги, периоды
CHROMIUM_PATH=/path/to/chrome npx playwright test     # e2e: десктоп + телефон
```

E2E-сценарий: Аня регистрируется → импортирует CSV → приглашает Мишу → Миша по ссылке
вступает в бюджет, добавляет трату с чеком и комментарием → Аня видит запись, открывает
чек и исправляет сумму → посторонний не может скачать чек.

## Устройство

- Next.js 16 (App Router, Server Actions), React 19, Tailwind 4, shadcn/ui.
- `src/lib/db.ts` — схема SQLite; суммы хранятся в копейках (integer).
- `src/lib/auth.ts` — сессии в httpOnly-cookie, пароли через scrypt. Каждый запрос и
  каждое изменение ограничены бюджетом из `requireContext()`.
- `src/lib/sheet-import.ts` — разбор CSV и сопоставление категорий (покрыт тестами).
- `src/app/files/[id]` — отдача чеков только участникам бюджета.

## Что дальше

1. Деплой: SQLite подходит для одного сервера (VPS, Fly.io с volume). Для serverless
   нужно перейти на Postgres, а фото — на S3-совместимое хранилище.
2. Повторяющиеся платежи (ЖКХ, связь, подписки) и прогноз на конец месяца.
3. Лимиты по категориям в мягком виде: «осталось 3 200 ₽ на кафе», без красных шкал.
4. Telegram-бот и голосовой ввод: «кофе 350» сразу превращается в запись.
5. Импорт банковских выписок (CSV/PDF Т-Банка и Сбера) и уведомления партнёру о новых тратах.
